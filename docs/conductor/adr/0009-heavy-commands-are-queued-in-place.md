# Heavy commands are queued in place when the session auto-approves them

The Claude Code package used to deny an unqueued heavy command and name the queued form, so every heavy run cost the agent a refused call and a retry. A mod's `tool.call` hook now rewrites the command in place into `queue.mjs run --queue=<q> -- bash -c '<command>'`, the same form the agent was told to type, but only when the engine's permission check (`$.tool.check`) allows that queued form outright: under `bypassPermissions`, or when the person's rules already allow it. Permission rules and the prompt match the rewritten text, not what the model asked for. In any other mode a rewrite would show the person a command they never saw the model write, and their allow rule for `pnpm test` would no longer cover it. So there the hook denies, naming the queued form and telling the agent to run it in the background, and the person's prompt shows that real command once. The rewrite is safe where it happens because it still passes the whole permission chain beneath the mod, unlike a `PreToolUse` hook's `allow`. The hook denies a foreground run on a full queue and a duplicate of a run already queued or running in every mode. The module triages the command text itself and starts Node (`tools/hooks/decide.mjs`) only for a heavy or queued command, so a light command costs no process. `queue.mjs` stays the one engine, harness-neutral, with the protocol at v1 (ADR 0007): a moved waiter's new place is its ticket's `createdAt`, the order key every copy already reads.
