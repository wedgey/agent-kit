# Lanes front-load review and wake on finished logs

An epic of five UI tickets ran for 938 minutes, of which 82 were the machine asleep. We replayed its lane transcripts minute by minute. About 115 minutes were lanes parked on background work that had already finished, about 95 were the repo's full local CI run up to four times per PR, and about 65 were review and verification run serially after every fix. Writing code took 8.

**Finished logs.** All four stalls were parked lanes, and in three of them no task notification was ever delivered, so the `parked` event at twice the quiet limit was the first signal, 24 to 31 minutes late. Each lane had named the log it waited on. A lane now launches background work with `echo "EXIT $?"` appended to a fresh log, and the watch reports `finished` once a named log ends on `EXIT`, was written after the lane parked, and has been still for two minutes. Replayed on the four stalls it fires on all of them, about three minutes after each job ended. We chose an explicit exit line over matching tool output such as "N passed", because a local CI run prints a pass line per stage and its log can be silent for six minutes mid-run; 67 of 516 lane waits in that epic would already have woken to a job still running. The mtime check stops an `EXIT` line from an earlier run in an appended log from firing while a rerun is still queued. The still window holds the nudge while a child of the job keeps writing. A nudge that lands too early costs one lane turn, and the lane parks again.

**Gate order.** Reviewers found real MUST issues on the first pass of nearly every ticket, so review stays. What cost time was its place: each fix restarted e2e, CI, reviewer and verifier in series, and verifiers found late issues on four of five tickets. The reviewer and an early verifier now run on the first full diff while the lane's own spec runs, the lane fixes everything in one batch, and a delta review, a mechanical verifier and the recorded proof run in parallel on that head. The same two roles still sign off on the head that merges.

**Smaller changes.** The verifier reuses the lane's warm dev server, because starting and seeding its own took 4 to 9 minutes and checked nothing the lane's server does not serve; it keeps its own browser session and seeded user so its look stays independent. A ticket may stack on a base whose review fixes are pushed, not only one that is merge-ready, and rebases with `--onto` because squash merges leave the base's commits behind. `LAND auto` lets a lane merge on the same evidence the orchestrator checked by hand; one lane waited 34 minutes for a go. It is opt-in.

None of this was piloted before it shipped. Revert a part if a merged PR needs a fix the old order would have caught, or a ticket's critical path grows.
