# The orchestrator hands over in place

ADR 0013 moved an epic to a fresh session when the orchestrator's context passed its limit. Each handover then needed the operator. On 2026-10-29 the Project 4 orchestrator started its successor with `claude --bg`, and the operator had to `/exit` and `claude attach` to it. It also cost every working lane a Context full report, a stop and a fresh start, because a subagent lane ends with its session.

Claude Code 2.1.312 lets a plugin's mod compact its own session (`$.session.compact`, the call `/compact` makes) and submit the next prompt (`$.prompt.submit`). So conductor's mod adds a `handover` tool. The orchestrator writes the epic's state to its issue, calls the tool with what the session must keep and the prompt that goes on, and ends its turn. When the turn ends, the mod compacts with those instructions and submits the prompt. The session is the same one, so its lanes, watches and message routes carry on, and nobody acts. A probe on 2026-10-29 compacted 9 s after its turn ended, went on from the submitted prompt with the kept ids, and still received a running subagent's notices.

We kept compaction over `/clear`. `/clear` ends the conversation, which a subagent lane does not outlive, and the new conversation would not know the lanes' ids. A compaction is steered by the `keep` text, and the issue stays the record if the summary drops something. A harness without the tool keeps ADR 0013's handover to a fresh session. How small the context is after a compaction, against a fresh session's, is not measured yet.

On 2026-10-30 every session the context note reached was a feature, a bug fix or a design session, not an epic. Each told the operator a fresh session would be cheaper and none called the tool, because the note sent only an epic's orchestrator to it. So the note now sends every session that is not a lane to hand over in place when its stage ends. A fresh session stays the fallback where the tool is missing.

A note sent once per 50k step gave no reminder after the operator answered a question, so sessions that rightly waited never handed over. The session's own agent now also hears the note on every operator prompt while past its limit, and it says to hand over when that prompt's work ends. A note that only pointed to the binding was ignored by sessions that never loaded the skill. So both notes name `mcp__conductor__handover`, though ADR 0002 keeps tool names in the bindings. The hook ships only in Claude Code's plugin, and without the tool the note falls back to suggesting a fresh session.

On 2026-11-27 a check of 98 main-session transcripts found 6 of 43 turns that ended with a question to the operator had automated prompts, such as lane notices, arrive before the operator replied, and in two the operator's next message never answered it. None of the 47 handovers ran over an open question, but only the rule against handing over while waiting kept it so, and that rule also kept an orchestrator with an open question from handing over at all. So the tool takes a required `questions` list. The mod keeps the questions through the compaction and adds them to the resume prompt, which tells the session to ask them again. A session still waits for an answer the stage in hand needs, and any other open question goes in the list.
