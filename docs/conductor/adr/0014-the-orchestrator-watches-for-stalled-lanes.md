# The orchestrator watches for stalled lanes

A lane reports by ending its turn, and the orchestrator wakes only on those reports. A lane whose model stream stalls never ends its turn, so it sends nothing. Claude Code's own stall notice does exist, but on 2026-10-29 we found four of them in our transcripts that reached an idle orchestrator 114, 169, 268 and 447 minutes after the lane's last entry, each when the session woke for some other reason. The epic playbook already had a "Silent too long" rule, but the orchestrator is asleep while it waits, so a rule it must remember has nothing to make it fire.

A hook cannot fire either, because hooks run on tool events and an idle session makes none. So the orchestrator starts `tools/watch-lanes.mjs` in the background for each lane, the same way a lane watches its own PR (ADR 0012). It reads the lane transcript's age once a minute and, past 15 minutes, its last entry. It exits when the lane owes a reply to a tool result or message, or is still in a tool call. Its completion notice wakes the orchestrator at no model cost while it waits. A lane that ended its turn is idle by design, waiting on its own watcher or background work, and never counts. The stalled lane of 2026-10-29 owed a reply to a tool result, so this would have found it about 15 minutes in.

The orchestrator then reads the lane's state from git, not its transcript, and continues the lane, which resumes it with its context. A second stall in the same stage replaces the lane from its pushed branch. Fifteen minutes is longer than any foreground command a lane runs, since its heavy checks run in the background, but a lane with a longer foreground call would be reported early. The script reads the transcript file itself, which the binding otherwise keeps out of the orchestrator's context. Its output is one JSON line.
